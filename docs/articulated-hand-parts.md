# Articulated physical hand parts

`HIGGS_QueryHandPartsInterface` is an additive copied C ABI for providers such as PPB. A provider supplies its fitted BOX geometry; HIGGS owns the physical bodies, keyframes, collision filters, movement compensation and teardown. This keeps the provider's fitting policy separate from HIGGS's authority over player hands. The existing palm remains HIGGS's palm. This interface adds up to eight parts per physical hand; PPB's current four boxes per hand fit directly, without claiming that a single palm box is an equivalent finger model. It does not implement PPB fitting, thumb geometry or capsule construction.

## Producer and fitting contract

At the actual prephysics boundary, HIGGS samples the resolved palm rigid body, skeletal hand and fifteen finger joints before invoking external prephysics callbacks. The copied frame includes broker epoch, producer sample/time, tracking generation and per-hand tracking observation/time, hand generation and model generation. Source0 is the actual resolved palm, source1 the skeletal hand, and sources2–16 the thumb/index/middle/ring/little joints0–2. Missing bones remain explicitly invalid. A model generation changes when the hand node, palm body, finger nodes or world epoch change. Tracking must be valid and at most100ms old; producer time is not hardware acquisition time.

In an external prephysics callback, a provider copies sources, computes a fitted part definition and submits a matching proposal. Local offsets use game units expressed in source axes, without implicit model scaling; half extents use metres. The source's `modelScale` lets the fitter apply scaling deliberately. Proper rotations, finite bounded dimensions, source IDs, unique part IDs and exact epoch/sample/model tickets are checked before admission. Missing/invalid/old source evidence fails closed. An update uses the existing set ID and exact request revision; it cannot silently overwrite a newer revision.

One provider owns a set for each physical hand. A lease lasts1–60000ms and is renewed by a new valid proposal. This is ownership of fitted geometry, not a gameplay hand grant or an alternative hand driver. HIGGS applies accepted geometry only after the external callbacks, on the same observed native maintenance thread. Calling the public API from another phase can enqueue a proposal but cannot mutate physics directly. Before native maintenance is installed, capability bits are zero and proposal submission is unsupported.

## Native ownership and receipts

HIGGS uses its existing published game constructors, allocator and world operations. Wrappers retain the world in which their bodies were created. Lifecycle removal always targets that creation world, including after a world switch. Pose-only changes reuse existing bodies. A changed half extent recreates only that part, refreshes the actual broadphase topology and obtains a new lifetime generation, rather than writing into a live shared shape and assuming broadphase freshness. The cost of continual dimension changes is therefore real and visible; providers should avoid needless refits.

Topology changes check Havok's actual critical-operation count under the creation-world write lock. Adds/removes are postponed while it is locked. An unexpected queued add remains retained and disabled until its real attachment is observed, then is removed before retrying; the add is never resubmitted. A queued removal is issued once and retains its world, body and wrapper/backpointer until actual detach is observed. Four bounded retirement rigs cover both rollback sides for each hand. Both potential rollback slots are reserved before moving or creating anything; insufficient retirement capacity leaves the current topology intact and the proposal pending. Exception cleanup transfers unresolved bodies into that owner, so stack unwinding cannot drop queued bodies. Release receipts wait for all matching active and retiring bodies.

Before any topology move, filter update or keyframe, the entire existing rig is checked under that world's write lock: retained body and box wrappers, actual world membership, owned shape and pending-operation state must still match. An externally detached or replaced member invalidates the set before any other member receives a command. The unvalidated copied body readback is cleared while the set ends; its prior applied revision remains historical evidence. A missing submitted native body cannot be guessed detached merely because its wrapper no longer exposes it.

Each owned body explicitly retains its box wrapper, and attribution snapshots retain the pair. After actual detach, HIGGS clears native body/shape back-pointers only when they still equal its own corresponding wrappers; foreign values are preserved. A separate bounded128-pair owner keeps the shape alive through final body-wrapper destruction, including delayed NiPointer references held by player-space tracking or another native consumer. Final pair reclamation waits until that owner is the body's sole Ni reference, then releases the body before the shape. One pair slot for each newly created body is reserved before any topology move; exhausted retention capacity postpones creation. External native body/shape references can outlive both wrappers with no dangling HIGGS back-pointer.

Each part follows the corresponding HIGGS palm's actual collision-filter word, including holding/two-hand suppression and player collision group. The existing HIGGS player-space body mechanism supplies locomotion compensation. Prephysics keyframes use the actual physics delta and HIGGS's existing clamped keyframe helper. No provider-supplied collision masks, direct bone pointers or arbitrary actuator callbacks are exported.

`requestRevision` and `appliedRevision` distinguish a copied proposal from actual native application. Body records distinguish actual sampled pose from the target of an issued keyframe. An applied command does not prove that physics reached its target. End is asynchronous: `RELEASED` or `BROKEN` is published after owned bodies were removed. Owner unregister, lease expiry, stale/lost tracking, model replacement and epoch changes invalidate the set. The service keeps32 bounded set receipt slots; completed slots can be reused, so historical IDs may eventually return `NOT_FOUND`.

## Canonical contact attribution

HIGGS classifies its owned parts as the correct left/right physical hand in the existing collision path. An immutable attribution snapshot retains native wrappers while contact readers use them; classification takes no part-registry mutation lock, and copied contact storage uses its own bounded service lock without engine calls. Native wrapper user data remains intact.

Every body record exposes both an observed Havok UID (`bodyKey`, scoped by epoch) and a HIGGS-assigned, nonreused runtime `bodyGeneration`. Live resolution requires both, avoiding the assumption that a reused UID is the old body. For contacts, `CopyContactAttribution` matches the exact epoch and `HIGGS_ContactObservation.sequence`, from a bounded512-record ring captured at the actual contact callback. It retains the original part/set/revision/owner/lifetime even after removal or UID reuse. Evicted or unavailable associations return `NOT_FOUND`; callers must not reconstruct them from a later UID lookup. These are enabled contact observations, not damage, impulses or a complete manifold report.

The separately negotiated `HIGGS_QueryHandPartsNativeInterface`, declared in `higgshandpartsnative.h`, lets native physics owners such as PLANCK classify an already borrowed live body by address comparison. Its read-only resolver never dereferences the input address, enters the hand broker, acquires an engine lock, mutates physics or exports a pointer. It compares against the immutable snapshot retaining HIGGS-owned wrappers and copies the attribution. The caller supplies its own valid body/world lifetime scope and must never cache or serialize the comparison key. Prepared disabled bodies can have appliedRevision0. Portable and early builds expose capability0/`NOT_READY`; the actual native resolver is installed by main maintenance. Gameplay mods continue using the copied gameplay table and exact contact correlation.

## Validation boundary

`python tests/run_hand_parts_tests.py --build-dir <external-directory>` compiles the production service closure, a C layout consumer, the actual native implementation with synthetic engine seams, actual physics classification and actual contact producer, plus a loaded-DLL C probe. A separate full native build compiles and links the real SKSE/Havok declarations. These checks establish source/ABI behavior; they do not constitute an in-game PPB migration, visual fit verification or runtime qualification of the existing reverse-engineered game bindings.
