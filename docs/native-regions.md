# Optional Body Slots spatial detection

`HIGGS_QueryNativeRegionsInterface` version1 exposes a copied native mouth/shoulder source frame and one optional synchronous spatial detector. It creates no Body Slots startup or link dependency. A consumer negotiates the table at PostPostLoad or later, registers an ordinary HIGGS hand client, then registers its detector. Missing Body Slots, an absent/incompatible table or a non-ready detector leaves the existing HIGGS detector available.

HIGGS supplies its actual HMD-relative mouth and shoulder spheres, resolved hand and palm positions, monotonic sample/time, world epoch, hand generation and private HMD/configuration source generation. Capture runs inside the actual native hand-update phase. Coordinates and radii use Skyrim world units; offsets already include the HMD transform scale, radii preserve the existing unscaled world-unit behavior. These legacy approximations are not PPB anatomical measurements or a VRIK final-pose guarantee. Mouth uses the palm, shoulders use the hand origin. The public [header](../include/higgsnativeregions.h) defines the fixed sphere ordering and masks.

Body Slots owns registered logical regions, geometry, scope and copied observations. Its callback returns only a correlated inside mask. It cannot consume input, acquire grants, mutate inventory, drive a hand or execute gameplay. HIGGS retains item eligibility, poison/book policy, velocity gates, haptics and the existing mutually exclusive consume/stash/drop executor. VRIK still owns body/virtual poses, PLANCK owns NPC physics and PPB owns anatomical geometry; this adapter adds none of those responsibilities to Body Slots or HIGGS.

Each spatial sample selects one detector. A valid `OK` result handles the entire sample, including mask0; native containment is then never calculated. Missing, removed, throwing, non-ready or malformed providers select native containment exclusively. Invalid source data selects outside without invoking either detector. The native comparison remains strict `distance < radius`; zero/negative radii disable that individual sphere. The shared Body Slots kernel and the old float kernel can differ extremely close to a floating-point boundary; this is not game-qualified numerical parity.

Preview and release predicates reuse a cached selection. The release admission and the point after requested-event callbacks refresh through the same selected provider, then revalidate the original HIGGS epoch/input-context/hand authority and selected action region. A reset or changed grant/menu cannot turn an old request into a new one. A rejected action becomes an ordinary drop and does not retry a different slot. Physical release requested by an existing HIGGS transaction still suppresses automatic consume/stash. New physical/operation grants serialize with the existing native-phase gate, so they cannot enter between the native authority check and game write. These bounded checks preserve the existing native executor; they are not a new generic action-offer API or a confirmed inventory receipt.

Detector registration uses the existing broker ownership, callback-in-flight accounting and client unregister lifetime. At most one active detector exists. No broker state mutex is held across its callback; the existing recursive native-phase gate is held. Callback code must not call HIGGS, retain source pointers, block or perform gameplay. Defensive reentry tests nevertheless verify safe pending removal/unregister and invalidation. Removal or unregister returns `OK` only after callbacks drain outside callback reentry; `Pending` does not permit unloading. Registration survives load/world changes, while copied source frames invalidate. `CopyFrame` provides last-observed evidence, not a current-source freshness guarantee.

`python tests/run_hand_tests.py --build-dir <external-output>` compiles the actual production service, C layouts, isolated DLL discovery, detector fallback/ownership/lifecycle/concurrency cases and extracted native capture/input methods. The complete native plugin build is a separate check. Neither offline execution nor compilation establishes running-game hook timing, tracking freshness, inventory effects, rendering or hardware behavior. No new address binding or CommonLib implementation is required.
