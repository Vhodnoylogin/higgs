# HIGGS architecture for VRIK HIGGS and PLANCK synergy

The additive [nonbutton proposal service](hand-use-proposals.md) now collects contact/dwell/posture opportunities into user-priority main-maintenance rounds. Pending proposals carry no authority; disjoint accepted proposals become ordinary HandUse sessions. Existing use is never preempted, and consumers must still adopt the service.

The proposed synergy gives Skyrim VR mods a shared foundation with clear owners. HIGGS owns all hand states, hand-use mechanisms, grip/trigger input and physical possession. Body Slots owns all slot mechanics, including spatial zones, runtime binding and interaction. VRIK owns body and virtual hand poses; PLANCK owns NPC physical animation, ragdoll lifetime and physical-hit processing; PPB supplies anatomical evidence. Consumers keep their gameplay, inventory-selection and equipment-proxy rules.

**Body Slots** owns creation, configuration, body/equipment binding, geometry, detection, activation and presentation. [Morphbench](https://github.com/Vhodnoylogin/morphbench) supplies offline authoring; VRIK supplies body/virtual-hand observations. Native14 compatibility is separate. Actual implementation and remaining gaps are distinguished in the [implementation ledger](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/implementation-status.md).

The `development` branch implements an initial [scoped restriction service](scoped-restrictions.md), independently negotiated from interface001. It addresses owned hand/collision suppression, expiry and lifecycle. The additional [hand broker](hand-broker.md) source now implements synchronous input selection, end-user priorities, owned grants, executor routing/receipts and finite physical operations. External content executors retain inventory/consumption authority. Native source qualification remains blocked by the compatible Havok dependency; complete transfer, dynamic support and other pending contracts below must not be inferred from isolated core/ABI tests. `main` preserves the upstream source, while all consolidated fork development remains in `development`.

A separate [read-only velocity table](velocity-observation.md) now copies the existing physical-hand history owner, explicit validity, producer-computed age and continuity metadata. It supplies part of the coherent-state requirement below. Consumers choose their age policy; this does not establish current palm/pose, physical possession, contacts, hardware sample time or input ownership. Standalone core/C/DLL checks pass; complete native-plugin and game qualification remain pending.

The only maintained source of the full concept and illustrative pseudo-ABI is [the English concept in Body Pouches](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/concept-en.md), with [a Russian counterpart](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/concept-ru.md). This file records HIGGS-specific requirements, not another copy of the concept. Body Pouches intends to adopt the architecture; it is not an available SDK or an agreement with the framework authors.

## Required architectural changes in HIGGS

1. **Broker grip/trigger before actions execute.** Publish observations with physical hand and sequence ID. Body Slots and other recognizers propose actions before defaults act. Resolve one consuming action using visible user priorities. The current implementation provides explicit INI priority overrides and a declared registration-order fallback; the additive input service also implements discard-only deferred hold/multi-tap reservations.

2. **Replace anonymous restrictions with owned leases.** Consumers request suppression for a named hand, feature and lifetime and release only their own effects. This replaces migrated uses of shared settings and `DisableHand`/`EnableHand`. Suppression and explicit item release remain separate operations.

3. **Provide correlated requests and confirmed results.** Grab, release, transfer and grip changes distinguish accepted, committed, completed, rejected and cancelled. Coordinate affected hands and item-instance ownership before mutation. Forward the assigned domain executor's receipt without taking over inventory or damage policy. Inventory commitment and physical grip are separate results; retries must not create duplicate items.

4. **Compose physical contributions through one final actuator per owned body.** Support grip, drive and constraint requests for weight, collision, penetration and climbing. Report effective acquisition, saturation, break and release. PLANCK validates NPC endpoints; HIGGS applies hand/weapon constraints. Player locomotion and fall rules remain with the climbing consumer.

5. **Publish coherent copied state.** Expose possession, grip geometry, motion, contacts and release observations with source, units, space, time, frame/physics IDs and body generations. Distinguish tracked controller, resolved palm and VRIK-rendered hand; identify the tracking-to-world transform and the observation Body Slots associates with its zone probe. The additive observations service supplies coherent controller/item motion, contact history and matching release snapshots with explicit coordinate/continuity provenance; rendered VRIK pose remains separate.

6. **Respect the slot-service/runtime boundary.** All slot mechanics, spatial offers, slot reservations and presentation readiness belong to Body Slots. HIGGS grants input/hand resources and performs physical requests; the content executor chooses and commits the item. Zone entry or a visible preview is not proof of possession. Unavailable/rebound slots invalidate undispatched offers; a started operation awaits its actual outcome rather than being treated as rolled back. Generic slot filters remain outside HIGGS inventory policy.

7. **Add a versioned lifecycle contract.** Keep interface 001 unchanged and negotiate new capabilities separately. Use copied records, request/executor identities and epochs; support callback removal with confirmed drainage. Apply physical changes at documented safe phases and invalidate pending resources on load, tracking loss or provider shutdown. The offline editor has no runtime dependency on HIGGS.

The current [001 interface](../include/higgsinterface001.h), [API implementation](../src/pluginapi.cpp) and [hooks](../src/hooks.cpp) are integration points, not proof that these services exist. Internal repairs still require their own source/build/runtime verification.

CommonLib is the second synergy level: reuse existing engine primitives and move address handling and repeated technical operations into verified library methods. Input arbitration and physical-possession decisions remain HIGGS services. Under that shared contract, VR Climbing and Immersive Harvesting can request hand actions without recreating common restrictions or patching each other's reservation mechanisms.
